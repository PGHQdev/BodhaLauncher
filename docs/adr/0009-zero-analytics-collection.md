# Analytics: zero collection at v1

Bodha transmits no analytics. All product metrics in the analytics spec (#25) — intentional-session ratio, Focus completion, retention — are computed on-device and shown to the user. Play Data Safety declares no analytics collection; the claim is enforced by construction and scoped honestly: crash/ANR and install data come from Play vitals/Console (no SDK), and purchase data necessarily reaches RevenueCat and is declared as purchases. The on-device event log uses a schema that could support a later explicit opt-in flush, so reversing this post-launch is an opt-in feature, not a rewrite. Alternatives rejected: Firebase (Advertising ID + IP by default — conflicts with the DoD privacy constraint), hosted privacy-first providers (Aptabase/TelemetryDeck — still a declared collection and an asterisk on "nothing leaves your phone"), in-house Workers+D1 counts (same asterisk, plus infrastructure). Vendor survey: `docs/research/analytics-options.md` on branch `research/analytics` (issue #41). Resolved in issue #42.
