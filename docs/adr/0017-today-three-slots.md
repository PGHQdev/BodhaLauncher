# Today: three fixed slots, no ranking, named degraded states

Today is a short page of three named slots in a constant order — **intention**, **day**, **digest** — with a date header. Nothing on it is ranked. Spec #5's "maximum six cards, sorted by urgency and relevance" is dropped whole: a ranker on the day surface owes an explanation per card that nothing here can give, and ADR 0014 has already refused to fake ranking tiers rather than ship an order it could not justify. Fixed order means the surface is the same shape every morning and can be read at a glance instead of scanned.

Today **owns the daily intention**. One store, one editor, one empty state — all here. Home renders the same value read-only as the Centered Axis voice (ADR 0010) and taps through to Today, which retires the temporary editor `HomeScreen.kt` marked as pending this decision. ADR 0003 already said Today shows the "set today's intention" state; this makes that the only place it appears.

The **day slot** shows every event of the current day that has not yet ended, earliest first, read from `CalendarContract.Instances` (it expands recurrences; `Events` does not) across every calendar with `Calendars.VISIBLE = 1`, dropping instances the user has declined. All-day events render as untimed rows above the timed ones. Events fall off as they end. There is no cap and no scroll horizon: a day is finite, so "no infinite scrolling" holds by construction. A single next-event row was rejected as answering less than the lock screen already does, against ADR 0011's "Today owns the day". Bodha ships **no calendar picker** — the user's calendar app owns that toggle, and a second one that can disagree with it is a setting earning nothing under the rule #95 will set. When no events remain, and only then, one row shows tomorrow's first event under a Tomorrow label: a bounded peek, not a horizon, and the reason Today still says something useful at 9pm.

The **whole surface runs on the 4am day key** (ADR 0003), not the civil date, and the date header shows that key's date. At 1:30am the intention, the day and the header agree it is still the previous evening, the 9am meeting appears under Tomorrow — which is how people speak at 1:30am — and a 2am flight still counts as tonight because it falls before the boundary. One `localDayKey()` serves both slots. Showing the key's date rather than hiding the date makes the boundary legible: a user seeing yesterday's intention can see why it still stands.

The **digest slot** shows one count per non-empty ADR 0015 section — People, Time-sensitive, Updates, Silent — with zero sections omitted, and no app names or previews. The card says how much is waiting and of what kind; the inbox says the rest. A single total was rejected because it cannot distinguish a morning of promos from three people needing an answer, which is what the sections exist for; app names were rejected because they reconstruct the system shade on the day surface that ADR 0015 explicitly declined to replace.

**Every empty slot names its cause.** Permission not granted: the slot states what it would show and offers a turn-on that opens the existing `Capability.Calendar` or `Capability.NotificationAccess` education screen via `EducationEntry.FeatureTouch` — Today never fires a system dialog because the user swiped there. Granted with nothing to show: a real sentence ("Nothing left on the calendar today", "Nothing waiting"). No calendars configured on the device: its own line, because telling a user their day is clear when Bodha has nothing to read is a lie, and offering a permission that would reveal nothing is a dead end. This follows ADR 0013's rule that absence is a named state, never a zero.

**Three taps, no other gestures.** Tap the intention to edit, tap an event to open it in the calendar app, tap the digest to open the inbox. Spec #5's swipe-right-to-complete, swipe-left-to-snooze and long-press-to-pin-hide-or-change-source all die with the feed: fixed slots have nothing to reorder or hide, completing a calendar event is not a launcher's business, and the one place handled and snooze mean something is the inbox, where ADR 0015 put them acting on the real notification.

Today is **unchanged during a Focus session** — same slots, same content. Focus is root while it runs (ADR 0011), so back already returns to it; a Focus strip here would be a second affordance to the place back already reaches, which is the reasoning ADR 0011 used to drop pinch. Hiding the digest during Focus was rejected too: ADR 0012 gave Focus no notification control, so suppressing it would invent a guarantee Bodha does not make while the notifications keep arriving.

Three of spec #5's elements are **dropped outright**. "One next task" has no source — ADR 0012 already refused to build a task system to satisfy an optional spec field, and the connectors that would supply one are Pro and later. "Time-sensitive item" duplicates ADR 0015's Time-sensitive section. "Resume cards" needs a document store nobody has designed, could only ever hold SAF-picked files, and its absence makes `Capability.Documents` and its education screen dead code, to be removed with this work.

Today is **free and uncapped** (ADR 0005, which lists "Today + daily intention, notifications inbox"); the Pro Google Calendar API connector is a different thing from the on-device Calendar Provider this slot reads. Today adds **no new store of its own**: calendar reads live and the intention store already exists. The digest's counts are the one exception, decided in #161 — they must still describe the day after a reboot or a cleared shade, so they read from ADR 0015's metadata-only notification store rather than the live shade; the store belongs to the inbox, and Today only reads it.

Accepted cost, handed to #96: a never-onboarded Today is three asks stacked — set an intention, turn on calendar, turn on notification access. Which of those onboarding requests, and which it defers to first touch, is onboarding's decision to make, not this surface's to paper over.

Resolved in issue #101.
