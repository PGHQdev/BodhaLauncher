# Home actions: pins render to eight, suggestions never push past four

Home's action list takes a two-tier cap: **user pins render up to eight; inferred suggestions only ever fill up to four total**, so suggestions never grow the list past four and pins alone are what can. This resolves a conflict two documents shipped in good faith: spec #3's "at most four suggested or pinned actions" ("a decision I can actually make rather than a menu I scroll") and ADR 0018's essentials copy, which suggests picking four to eight. Under a flat cap of four, a user who took the onboarding copy at its word had picks silently stored but never rendered — the one outcome both documents would call wrong.

The split honours what each rule was actually protecting. Spec #3's four was about Bodha not turning Home into a menu — and every action past four here is one the user placed by hand, which is the opposite of Bodha deciding. ADR 0018's four-to-eight stands as written: every essentials pick is visible on Home the moment onboarding ends. Raising the flat cap to eight was rejected because it would let *inferred* suggestions build the very menu spec #3 refused; keeping four and rewriting the onboarding copy was rejected because eight deliberate pins is a legitimate Home and the cap was never aimed at deliberateness.

Mechanically: `resolveHome` takes pins up to `MAX_PINS` (8); suggestions fill only the room left under `MAX_ACTIONS` (4), so with four or more pins no suggestion appears. Home's add-a-pin row shows while the list is under eight. Spec #3 is superseded on this line, as ADRs are wherever they speak.
